# Architecture

## Purpose

This prototype is a local, offline-first decision-support dashboard for SIH26085. It couples deterministic demo rainfall, an inferred terrain grid, simulated drainage-capacity scenarios, derived flood bands, road impact, and flood-aware routing for one Chennai pilot zone.

The implementation is intentionally reduced-order. It is not a city-wide hydrodynamic digital twin and it does not use real underground pipe or invert-level data.

## Runtime Shape

- Frontend: React 18, TypeScript, Vite, Tailwind CSS, MapLibre GL JS, Recharts.
- Backend: FastAPI, Pydantic v2, Uvicorn.
- Simulation: pure Python with numpy for deterministic grid math.
- Routing: NetworkX graph built from `data/roads.geojson`.
- Data: bundled GeoJSON and JSON files generated by `scripts/generate_demo_data.py`.

The demo runs with two local processes:

- `uvicorn app.main:app --reload --port 8000`
- `npm run dev`

## Request Flow

1. The frontend loads `/api/health`, `/api/scenario`, `/api/drainage`, and `/api/critical-infrastructure`.
2. The default scenario is submitted to `/api/nowcast`.
3. The frontend fetches `/api/forecast` once for the scenario key and uses the returned `NOW / T+30 / T+60 / T+120 / T+180` sequence for timeline clicks.
4. Map layers are updated from the active forecast step in client state.
5. Route calculations call `/api/route`, which reuses the current scenario's computed road risk.

## Adapter Boundary

The `backend/app/adapters` package defines the future integration points:

- `rainfall_adapter.py`
- `dem_adapter.py`
- `drainage_adapter.py`

Demo adapters read bundled local files. Live adapters are deliberately stubbed. If live mode is requested and an adapter is unconfigured, service code catches the failure, logs it, serves demo data, and reports Demo mode through `/api/health`.

## Simulation Boundary

The model lives in `backend/app/simulation/model.py`. Its module-level disclaimer is part of the implementation contract:

`Reduced-order demonstration model. Not a validated hydrological/hydraulic model. Coefficients are illustrative and tuned only to produce a plausible, explainable demo response.`

The model emits bands and confidence levels rather than point depth values. Drainage capacity and degradation are always treated as simulated scenario inputs.

## Determinism

Demo data is generated deterministically. Scenario runs derive a stable seed from rainfall intensity and drainage condition. The seed is only used for small repeatable cell variation, and no request-time random draws are used.

## Resilience

Missing GeoJSON files are loaded as empty valid FeatureCollections. Request validation returns 422 responses with structured detail. Frontend fetch failures keep the last successful state visible and show inline retry/status messaging.
