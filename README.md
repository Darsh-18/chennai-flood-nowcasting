# Chennai Urban Flood Nowcasting & Decision Support Prototype

## 1. Project Overview

This is a working, locally runnable prototype for SIH26085, Ministry of Earth Sciences / NCMRWF, Disaster Management theme. It demonstrates a Chennai pilot-zone flood nowcasting workflow: rainfall to runoff, drainage stress, surface flood bands, road impact, and emergency routing.

The map domain is a bounded 5-15 km² pilot basin labeled `Pilot Zone (illustrative boundary)`. It is a reduced-order demonstration model, not an operational flood forecast system.

## 2. Architecture

- Frontend: React 18, TypeScript, Vite, Tailwind CSS, MapLibre GL JS, Recharts.
- Backend: Python 3.11, FastAPI, Pydantic v2, Uvicorn.
- Simulation: pure Python with numpy-backed deterministic grid math.
- Routing: NetworkX graph built from `data/roads.geojson`.
- Data: local GeoJSON and JSON generated by `scripts/generate_demo_data.py`.
- Runtime: two localhost processes, no Docker, cloud service, database, or network dependency for Demo mode.

See `docs/ARCHITECTURE.md` for the request flow and adapter boundaries.

## 3. Setup

Backend:

```bash
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python ../scripts/generate_demo_data.py
uvicorn app.main:app --reload --port 8000
```

Frontend:

```bash
cd frontend
npm install
npm run dev
```

## 4. How To Run

Run the backend first, then the frontend.

- Frontend: `http://localhost:5173`
- Backend health: `http://localhost:8000/api/health`
- FastAPI Swagger: `http://localhost:8000/docs`

The judge demo path is:

1. Open the dashboard.
2. Select Heavy rainfall, Normal drainage, T+60, then run nowcast.
3. Click a flooded cell to inspect drivers.
4. Switch drainage to Severe and run again.
5. Open Routing, choose Demo Hospital Node to Demo Relief Center Node, and calculate the route.
6. Select T+120 on the timeline.
7. Open Data Status.

## 5. Demo Mode Explanation

Demo mode is the default. It uses bundled local data and deterministic simulation outputs, so the app runs fully offline.

Live mode is represented through rainfall, DEM, and drainage adapter interfaces. The live adapters are intentionally unconfigured in this prototype. If live mode is requested and an adapter fails, the backend falls back to Demo mode and `/api/health` reports `Fell back to Demo Mode`.

## 6. Data Format

The repository contains these generated data files:

- `data/pilot_boundary.geojson`
- `data/roads.geojson`
- `data/drainage_network.geojson`
- `data/critical_infrastructure.geojson`
- `data/dem_proxy.json`
- `data/rainfall_scenarios.json`
- `data/data_status.json`

Every layer and derived value uses one of these labels:

- `OBSERVED`: bundled rainfall replay inputs.
- `DERIVED`: model outputs calculated from rainfall, runoff, drainage stress, and terrain factors.
- `INFERRED`: coarse terrain and accumulation factors approximating a 30 m-class DEM baseline.
- `SIMULATED`: illustrative boundary, road graph, drainage network, and scenario controls.

Drainage capacity and degradation are simulated scenario values only. They are not municipal stormwater-drain records.

## 7. How To Swap In Live Data Sources Later

Add implementations behind these adapter interfaces:

- `backend/app/adapters/rainfall_adapter.py` for IMD, Open-Meteo, or GPM IMERG rainfall feeds.
- `backend/app/adapters/dem_adapter.py` for Bhuvan or another DEM provider.
- `backend/app/adapters/drainage_adapter.py` for approved stormwater-drain GIS layers.

Keep the response schemas unchanged so the frontend remains stable. Adapter failures should continue to fall back to Demo mode instead of surfacing an error page.

## 8. Simulation Model Explanation

The backend model states:

`Reduced-order demonstration model. Not a validated hydrological/hydraulic model. Coefficients are illustrative and tuned only to produce a plausible, explainable demo response.`

Per grid cell, per time step:

```text
rainfall = lookup(rainfall_scenarios.json, rainfall_intensity, time_step)
effective_runoff = rainfall * runoff_coefficient * terrain_factor[cell]
base_drainage_capacity = drainage_network base capacity for the cell's catchment
degradation_multiplier = {normal: 1.0, degraded: 0.6, severe: 0.3}[drainage_condition]
effective_drainage_capacity = base_drainage_capacity * degradation_multiplier
excess_water = max(0, effective_runoff - effective_drainage_capacity)
accumulated_water[cell] += excess_water * accumulation_factor[cell]
depth_band = bucket(accumulated_water[cell])
confidence = confidence_for_horizon(forecast_minutes)
risk_level = derive_risk(depth_band, confidence)
primary_cause = argmax driver among {rainfall_intensity_score, drainage_stress_score, terrain_accumulation_score}
```

Water is passed toward the steepest-descent neighbor from the synthetic terrain proxy. Outputs are shown as bands only: `0-10cm`, `10-30cm`, `30-60cm`, and `>60cm`.

## 9. API Endpoint Reference

- `GET /api/scenario`: selectable rainfall, drainage, and horizon options.
- `POST /api/nowcast`: runs the full deterministic scenario chain.
- `GET /api/flood-state?scenario_key=heavy:normal:60`: returns flood cells for a scenario.
- `GET /api/forecast?scenario_key=heavy:normal:60`: returns `NOW / T+30 / T+60 / T+120 / T+180`.
- `GET /api/drainage`: returns the illustrative drainage GeoJSON.
- `POST /api/route`: returns normal and flood-aware route geometry, distance, ETA, and explanation.
- `GET /api/data-status`: returns layer status and honesty labels.
- `GET /api/critical-infrastructure`: returns demo hospital, fire station, and relief center nodes.
- `GET /api/health`: returns backend status and current mode.

## 10. Limitations

- No real drainage pipe, invert-level, pump, or outfall data is used.
- The DEM is a coarse 30 m-class proxy, not a survey-grade surface.
- The road network is illustrative and generated for a connected routing demo.
- Flood depth outputs are qualitative bands, not validated depth measurements.
- The prototype does not provide validated depth accuracy.
- The model is not a replacement for Chennai's operational systems or any other deployed flood platform.

## 11. Future Improvements

- Integrate IMD or GPM IMERG rainfall through the rainfall adapter.
- Replace the simulated drainage layer with authorized Chennai stormwater-drain GIS data.
- Calibrate coefficients against historical flood reports and field observations.
- Add persistent scenario logs for after-action review.
- Extend road impact with real traffic speed and closure feeds when authorized.
